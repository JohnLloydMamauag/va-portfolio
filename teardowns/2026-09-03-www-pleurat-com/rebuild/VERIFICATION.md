## Gate 7 — Honesty audit

**INFERRED / reconstructed (no source call site found):**
- Mosaic horizontal-scrub driver (`js/engines/mosaic-scrub.js`) — the real JS was never fetched (`build-analysis.md` Gotcha #2: lives in an out-of-scope route chunk). Reconstructed using the documented generic `Ve()`/`b` scroll-pin primitive (`js/engines/scroll-pin.js`, ported verbatim from `theme-CvJK8SGN.js.beautified.js:188-218`) driving a `translateX` pan across a 5×4 image grid. Pin container height (2880px) is the one EXTRACTED, exact number (`source/runtime-probes.json` stickyScenes).
- Chart-scene pin wiring (`js/engines/chart-scene.js`) uses the same primitive for the same reason; its diagram draw-on keyframes and 2385px pin height are EXTRACTED exact.
- "By the numbers" stat targets (10 / 80 / 45 / 12) are **invented placeholders**, not extracted data — the live site itself still ships broken `0+` placeholders (a confirmed live bug, `README.md` "Known issues"), and the real CMS values are not recoverable from this teardown. The task brief explicitly said not to ship literal `0+`, so round placeholder numbers were used instead and are called out here as non-authoritative.
- Hero street-scene walker rig and footer board-walk robot are simplified stick-figure/abstract SVGs, not the 472-line hand-rigged Commuter character (`Commuter-BHE77-Jm.js`) or the full building-list parallax scene — `build-analysis.md` itself rates the Commuter as "Hard — bespoke SVG illustration + rigging, not a code pattern to port." The real `sv-walk-*` CSS keyframes (14-stop thigh/knee/foot cycle) ARE ported verbatim and drive the simplified rig.
- Focus/Tracks tabs 2 and 3 show an explicit "not captured" placeholder instead of invented CMS copy — only track 1 of 3 was ever in the DOM capture (`content/04-focus-tracks.md`).
- Console widget (`js/engines/console-widget.js`) is a from-scratch reimplementation against the documented copy/DOM inventory (`content/03-console.md`), not a transcription of `Console-CyBRxdTz.js:780-1159` — rated "High complexity, bespoke interactive widget" in `build-analysis.md`. The typed-log line-delay ladder (130ms/line) is ported from the one piece of timing math that was documented.

**Hotlinked:** none — every REUSE-OK and REFERENCE-ONLY asset was copied locally into `rebuild/assets/` (fonts, tool-logo webp/svg, all 20 Sanity mosaic avifs) per the skill's asset rules for a study rebuild.

**REFERENCE-ONLY assets used locally (flagged per `assets/ASSETS.md`) — swap before any real deployment:**
- `assets/images/sanity-*.avif` (20 files) — Pleurat Shala's own project photography, not license-cleared for reuse.
- `assets/images/logo-claude.webp`, `logo-figma.webp`, `logo-cursor.webp`, `logo-supabase.webp`, `logo-vercel.webp`, `logo-openai.webp`, `assets/svg/logo-grok.svg`, `logo-github.svg`, `logo-tailwind.svg` — third-party brand marks.
- `assets/svg/favicon.svg` — site-owned mark.
- General Sans (Fontshare CDN link) and IBM Plex Mono (Google Fonts CDN link) are **REUSE-OK** and loaded the same way the original does.

**Substitutions (deliberate, not oversights):**
- **Theme-key bug NOT reproduced.** `build-analysis.md` documents a confirmed live bug: the original's FOUC script reads `localStorage['theme-pref']`, a key nothing in the app ever writes (the real toggle only ever writes `sv-theme`), causing a dark flash for returning light-mode visitors. This rebuild's inline FOUC script (`index.html` head) reads `sv-theme` directly instead — the bug is fixed, not carried over, per the skill's guidance that a rebuild "has no obligation to copy it."
- **`.site-root` default theme corrected from an initial wrong assumption.** Early in this build the rebuild shipped with `.site-root.is-dark` on by default. Cross-checking `screenshots/desktop-full.png` and `desktop-full-light.png` (both visibly light/cream) against `runtime-probes.json` (dark `<body>` bg) revealed the real site's two token systems are independent: the outer chrome (`data-theme`, System 2) defaults dark, but the visible `.site-root` content (System 1, amber/paper) defaults LIGHT — a first-time visitor has no `sv-theme` key, so React never adds `is-dark`. Fixed to match; nav/footer are additionally hardcoded to a fixed cream-panel/dark-ink combination that does not flip with the toggle, per `build-analysis.md`'s "Typography and Spacing" note that "header/nav/h1-h3/footer all render a fixed dark ink... they sit on cream/paper panels, not the page background."
- **Route transitions**: this is a single static page (no client router), so the curtain's route-change choreography (`js/engines/curtain.js`, timings ported verbatim: `K=8` cols, 38ms stagger, 746ms cover, 340ms hold, 786ms+60ms reveal) is wired to every `data-stub` internal link so the mechanism is demonstrable even though there's nowhere else to route to.
- **Analytics (PostHog, GA4) intentionally omitted** — not part of the animation/engineering study, would only add network noise to a local rebuild.
- **AI-tools grid is static, not `Fe()`-driven**, after determining its per-item opacity values (`0.92`, `0.84`, `0.74`, `0.98`, `0.9`, `0.9`) are permanent "recency of use" styling (confirmed already-settled at `scrollY=0` in `layout-manifest.json`, and documented as such in `content/06-ai-tools.md`) rather than the `Fe()` stagger-reveal target — that call site was re-attributed to Console's small `figma/cursor/claude` tag pills instead (`js/main.js` comment explains the reasoning).

**Known harness artifact (not a rebuild defect):** the ad-hoc verification script's naive `y < 5000` filter for "tool logo" rows also matched 5 off-screen mosaic-track `<img>` rows at the same page-Y range in `layout-manifest.json`, and its flat index comparison doesn't skip the gap where "Meta" (a `<span>`, not an `<img>`) sits in the DOM order. Manually realigning indices (see the Gate 1 note above) confirms all 9 real tool logos match position/opacity exactly; this is called out so the raw script output isn't misread as a positioning bug.
